# llm-proxy frontend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The web interface of llm-proxy — user cabinet and admin panel — built, tested, and shipped as a container image that the backend's `docker-compose.yml` runs.

**Architecture:** A React single-page application built by Vite into static files, served by nginx which also reverse-proxies `/api` to the backend. Server state lives in TanStack Query; there is no global store. Types come from the backend's OpenAPI contract, so a drifting contract breaks the build rather than the runtime.

**Tech Stack:** React 19, TypeScript (strict), Vite, React Router, TanStack Query, CSS Modules, `openapi-typescript` + `openapi-fetch`, Vitest + Testing Library + MSW, Playwright, uPlot, nginx (alpine).

**Spec:** `docs/specs/2026-09-22-frontend-design.md`. **Contract:** the backend repository's `api/openapi.yaml`, vendored here as `api/openapi.yaml`.

## Global Constraints

- Repository: `github.com/elleqt/llm-proxy-frontend`. Node 22 LTS, npm.
- No hostname, domain, realm, group name, IP or deployment-specific path anywhere — code, tests, comments, fixtures. `example.com` and generic names only. The repository will be published.
- No UI kit. Components are our own, on CSS Modules and the design tokens in Task 1.
- The client stores nothing in `localStorage` except `theme` and `lang`. It never holds a session id, and holds a token secret only in memory for the tab that issued it.
- Human-readable text comes from the i18n dictionaries keyed by the error `code` from the API, never from the server's `message`.
- Every behaviour is covered by an automated test. Visual appearance is the only thing checked by eye.
- All API types are generated from `api/openapi.yaml`. Hand-written request or response types are prohibited.
- `401` sends the user to `/login` — **except** code `invalid_credentials`, which only `POST /api/auth/login` and `POST /api/auth/password` return: it rejects what was typed, the session survives, and the screen shows the error in place. `403` with code `password_change_required` sends them to `/password`; any other `403` is shown as a refusal in place. On sign-in and sign-out the query cache is cleared and `me` re-seeded, so one user's data never renders for another; after a successful password change `me` is refetched before navigating.

## Task 1: Scaffold, contract types, design tokens, theme and language

**Files:** `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`, `src/main.tsx`, `src/app/*`, `src/shared/styles/tokens.css`, `src/shared/i18n/*`, `src/shared/api/*`, `api/openapi.yaml`, `scripts/sync-contract.sh`, `.gitignore`.

- [ ] **Vite + React + strict TypeScript.** `npm run build` produces `dist/`. `npm test` runs Vitest. The dev server proxies `/api` to `VITE_BACKEND_ORIGIN` (default `http://localhost:8080`).
- [ ] **Contract.** Vendor the backend's `api/openapi.yaml` into `api/openapi.yaml`. `scripts/sync-contract.sh` copies it from `../backend/api/openapi.yaml` and fails if the source is missing. `npm run gen:api` runs `openapi-typescript api/openapi.yaml -o src/shared/api/schema.d.ts`; the generated file is committed, and a test fails when regeneration would change it.
- [ ] **API client** `src/shared/api/client.ts` on `openapi-fetch`, `credentials: "same-origin"`. It normalises failures into one `ApiError { status, code, field? }`. Unauthenticated (`401`) and restricted (`403` + `password_change_required`) are raised as distinct error classes the router reacts to.
- [ ] **Design tokens** `src/shared/styles/tokens.css` — exactly these seven variables and four themes, matching the existing instruction page:

- [ ] **Pre-paint script.** An inline script in `index.html` `<head>`, before any stylesheet or module, sets `data-theme` and `data-lang` on `<html>` from `localStorage`, validating against the allowed values, falling back to `auto` and `en`, and surviving a `localStorage` that throws. Keep its source in `src/app/prepaint.ts` as the single definition and inline it at build time (`transformIndexHtml`), so the test and the page run the same code.
- [ ] **i18n.** Typed dictionaries `en` and `ru` with identical key sets (a test fails on a key missing from either). A `useT()` hook. Error codes from the contract map to messages; an unknown code falls back to a generic message rather than showing the raw code.
- [ ] **Switches.** Theme and language switches in the page header, in the instruction page's style (small bordered buttons, `aria-pressed` on the active one), writing through to `localStorage` and the `<html>` attributes.
- [ ] **Router and guards.** React Router with an auth boundary: unauthenticated → `/login`; a restricted session reaches only `/password`; `/admin/*` requires `role === "admin"`, otherwise a not-found view.

**Tests:** pre-paint (valid stored values, invalid values, throwing `localStorage`, nothing stored); dictionary key parity; client error normalisation for `401`, `403 password_change_required`, other `403`, `422` with a field, and a network failure; guard redirects.

**Acceptance:** `npm run build` and `npm test` pass; `npm run gen:api` produces no diff.

## Task 2: Component library

**Files:** `src/shared/ui/*` — `Button`, `TextField`, `Select`, `Checkbox`, `Toggle`, `Table`, `Card`, `Badge`, `Modal`, `Toast`, `Tabs`, `CopyField`, `EmptyState`, `Spinner`, `Chart`, each with a `.module.css` and a test.

- [ ] Keyboard operable, visible focus ring in `--accent`, correct ARIA roles, animation disabled under `prefers-reduced-motion`.
- [ ] `Modal`: traps focus, restores it to the opener on close, closes on Escape, labelled by its title.
- [ ] `CopyField`: monospace value, a copy button with a confirmation state, and a warning that the value will not be shown again. It keeps nothing after unmount. It is the one component for a new token, a temporary password and a vendor sign-in link.
- [ ] `Table`: semantic `<table>`; sortable headers are buttons with `aria-sort`.
- [ ] `Chart`: a thin wrapper over uPlot taking already-aggregated series; it computes nothing. Themed from the CSS variables and re-themed on theme change.
- [ ] `Toast`: a polite live region.

**Tests:** behaviour, not markup — the modal's focus trap and restore, Escape, `CopyField` copying through the clipboard API and showing its warning, `Table` sort toggling, `Toggle` keyboard activation.

## Task 3: Sign-in, password change, cabinet, connect

**Files:** `src/pages/login`, `src/pages/password`, `src/pages/cabinet`, `src/pages/connect`, `src/features/issue-token`, `src/features/revoke-token`, `src/entities/*`.

- [ ] **`/login`** renders from `GET /api/auth/config`: the form when `localLogin`, the identity-provider button (`/api/auth/oidc/start`) when `oidc.enabled`, both when both. `invalid_credentials` shows one message for every refusal. `locked_out` shows when to retry, from `Retry-After`. `?error=oidc_forbidden|oidc_failed` shows the matching message.
- [ ] **`/password`** — the only screen a restricted session reaches. It asks for the current password only when the session is not restricted. The password rules are shown before submit. On success it refetches `me` (a stale `restricted: true` would bounce the user straight back here) and goes to `/`. In a restricted session a `401 invalid_credentials` can only mean the temporary password expired: the screen says so with the password-change text (not the sign-in one) and offers sign-out, since the user cannot recover otherwise. The header offers sign-out on every authenticated screen; sign-in and sign-out clear the query cache.
- [ ] **`/` cabinet.** Token table: label, prefix, created, last used ("never used" stated explicitly, not a dash), state. Issue: a modal asking for a label, then the secret once in `CopyField` with a link to `/connect`. Revoke: a confirmation naming the label. Usage: a period switch (24 h / 7 d / 30 d), a `Chart` of tokens over time per model, and totals.
- [ ] **`/connect`** renders instruction blocks for Claude Code, omp and plain curl from `GET /api/connect`'s `apiBaseURL`. The token just issued in this tab (memory only) is substituted when present; otherwise a placeholder and a link to issue one. A troubleshooting section explains 401 and 403 answers.

**Tests:** MSW-backed scenarios — sign in, restricted redirect, change password, issue a token and see the secret once (gone after closing the modal and re-rendering), revoke with confirmation, connect with and without a fresh token.

## Task 4: Admin screens

**Files:** `src/pages/admin/*`, `src/features/policy-editor`, `src/features/provider-login`.

- [ ] **`/admin/users`.** Table: name, email, kind (badge), sign-in methods, role, status, last activity. Filters by kind, status and sign-in method; text search. "Create user" and "Create service account" are separate actions. Creating a human with `password` sign-in shows the temporary password once in `CopyField` with its expiry; with `oidc` it states that the first sign-in with that address will claim the account.
- [ ] **User card** `/admin/users/:id`: details, block/unblock with confirmation, role, password reset (temporary password shown once), the policy editor, the account's tokens with last use, and — for a service account — issuing a token on its behalf. Recent requests and audit events from `/activity`.
- [ ] **Policy editor.** Rules as provider + model pattern; provider picker and model suggestions from `GET /api/admin/catalog`; free text allowed. A live preview from `POST /api/admin/policy/preview` beside it, with a standing note that a wildcard also covers models published later. Per-rule errors inline. When `policySource === "idp"` it is read-only, explaining that the identity provider's groups own this policy.
- [ ] **`/admin/providers`.** Table: provider, label or email, status, last error, last refresh, quota per window (used ratio as a bar, reset time). Disable/enable and remove with confirmation naming the account. **Add account** is a three-step wizard: pick provider → `CopyField` with the sign-in link and a countdown to `expiresAt` → paste the URL the vendor sign-in ended on. Expiry is shown as it happens, not discovered by a failed submit.
- [ ] **`/admin/settings`.** Typed fields (`proxyURL`, `requestRetry`, `maxRetryInterval`) and a YAML editor as the escape hatch. "Check" is a dry run showing the diff; "Apply" is a separate confirmed action. `forbidden_setting` names the field. The price list is an editable table.

**Tests:** MSW-backed — each kind of account's one-time output; the policy preview updating and its read-only IdP state; the provider wizard including expiry; settings dry run then apply; a non-admin at `/admin` sees not-found.

## Task 5: Container image and end-to-end run

**Files:** `Dockerfile`, `nginx/default.conf.template`, `.dockerignore`, `e2e/*`, `playwright.config.ts`.

- [ ] Multi-stage: `node:22-alpine` builds, `nginx:1.27-alpine` serves. The final stage runs as non-root, has no Node and no sources. **The alpine nginx variant is required**: the backend compose healthcheck uses BusyBox `wget`.
- [ ] nginx: long cache for hashed assets, `no-cache` for `index.html`; SPA fallback; `/api/` proxied to `${BACKEND_ORIGIN}` via nginx's environment template mechanism, forwarding `Host`, `X-Forwarded-For` and `X-Forwarded-Proto`; `server_tokens off`; a `Content-Security-Policy` that permits no inline script except the pre-paint script's hash.
- [ ] Align the backend compose `frontend` service with the image's port and healthcheck (that file is in the backend repository — coordinate, do not edit it from here).
- [ ] Playwright against the real stack: the bootstrap admin signs in with the printed temporary password, is forced to change it, issues and revokes a token, creates a user and edits the policy with a preview. No vendor is needed for these flows.

**Acceptance:** the image builds; the compose stack reports the frontend healthy; Playwright passes; every screen checked by eye in all four themes and both languages.
